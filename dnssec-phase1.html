[Phase 1] Dual-OS Provisioning

📖 Architecture Concept Explainer

To accurately simulate global routing collapse inside an Enterprise active-directory structure, we must provision a cross-platform Private Virtual Network.

We deploy two nodes:
1. vm-dns-server: The authoritative Linux gateway running BIND9.
2. vm-dns-client: The native Windows Server 2022 downstream app node.

💻 PowerShell SRE Execution Matrix

> az group create --name rg-dnssec-lab --location centralus
> az network vnet create -g rg-dnssec-lab -n vnet-dnssec --address-prefix 10.0.0.0/16 --subnet-name snet-internal --subnet-prefix 10.0.1.0/24
> az vm create -g rg-dnssec-lab -n vm-dns-server --vnet-name vnet-dnssec --subnet snet-internal --image Ubuntu2204 --admin-username sreadmin --admin-password "SreDevOps2027!" --public-ip-sku Standard --size Standard_D2s_v7
> az vm create -g rg-dnssec-lab -n vm-dns-client --vnet-name vnet-dnssec --subnet snet-internal --image Win2022Datacenter --admin-username sreadmin --admin-password "SreDevOps2027!" --public-ip-sku Standard --size Standard_D2s_v7
# Verify Server Deployment:
> az vm show -g rg-dnssec-lab -n vm-dns-server -d --query "provisioningState" -o tsv
# Verify OS Client Deployment:
> az vm show -g rg-dnssec-lab -n vm-dns-client -d --query "provisioningState" -o tsv
# Extract environmental topology variables straight into your current Shell namespace:
> export SERVER_PUBLIC_IP=$(az vm show -d -g rg-dnssec-lab -n vm-dns-server --query publicIps -o tsv)
> export SERVER_PRIVATE_IP=$(az vm show -d -g rg-dnssec-lab -n vm-dns-server --query privateIps -o tsv)
> export CLIENT_PUBLIC_IP=$(az vm show -d -g rg-dnssec-lab -n vm-dns-client --query publicIps -o tsv)
> echo -e "Linux Server: $SERVER_PUBLIC_IP | Private: $SERVER_PRIVATE_IP | Windows Client (RDP): $CLIENT_PUBLIC_IP"
